# Terraform

This directory contains the initial Infrastructure as Code layer for SmartLift.

Current scope:

- Kubernetes provider
- application namespace
- observability namespace
- backend ConfigMap
- backend Secret
- PostgreSQL Secret
- PostgreSQL headless Service
- PostgreSQL StatefulSet
- backend Deployment
- backend Service
- backend HorizontalPodAutoscaler
- frontend nginx ConfigMap
- frontend Deployment
- frontend Service
- frontend Ingress
- Prometheus ConfigMap, Deployment, Service
- Alertmanager ConfigMap, Deployment, Service
- Grafana Secret, ConfigMaps, Deployment, Service
- node-exporter Deployment and Service

The current Terraform layer targets the same backend runtime that was already defined in `k8s/backend`, but now manages it declaratively through Terraform.

## Structure

- `versions.tf`
- `providers.tf`
- `variables.tf`
- `main.tf`
- `outputs.tf`
- `terraform.tfvars.example`
- `environments/dev/dev.tfvars`
- `environments/prod/prod.tfvars`

## Prerequisites

- Terraform `>= 1.6`
- a working Kubernetes cluster
- a valid kubeconfig and context
- `metrics-server` installed in the cluster for HPA
- a published backend image
- a reachable PostgreSQL instance

## Usage

1. Copy example variables:

```bash
copy terraform\\terraform.tfvars.example terraform\\terraform.tfvars
```

2. Edit:

- `frontend_image`
- `backend_image`
- `db_username`
- `db_password`
- `jwt_secret`
- `kube_context`
- `grafana_admin_password`
- `frontend_ingress_host`

3. Initialize:

```bash
terraform -chdir=terraform init
```

4. Plan:

```bash
terraform -chdir=terraform plan -var-file=environments/dev/dev.tfvars
```

5. Apply:

```bash
terraform -chdir=terraform apply -var-file=environments/dev/dev.tfvars
```

## Notes

- secrets are parameterized, not hardcoded in `.tf`
- if `db_url` is left empty, Terraform wires the backend to the in-cluster PostgreSQL service automatically
- Prometheus and Grafana configs are loaded from the repo files under `observability/`
- frontend nginx config is generated by Terraform so `/api` points to the Kubernetes backend service
- observability storage currently uses `emptyDir`, which is acceptable for demo but not for production persistence
- PostgreSQL is now managed as a single-replica StatefulSet
- Ingress is optional and controlled by `ingress_enabled`
